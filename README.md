# Wave

Личный десктопный плеер: вставляете ссылку из YouTube, SoundCloud, Spotify или Яндекс Музыки — Wave скачивает аудио
в лучшем доступном качестве, хранит его у вас на диске, находит текст и включает караоке, как в Spotify.
Проект некоммерческий, для личного использования.

## Запуск

```bash
npm install
npm run dev        # режим разработки с горячей перезагрузкой
npm run build && npm run start   # собранная версия
npm run dist       # установщик (AppImage/deb, на Windows/macOS — свои форматы)
```

Нужен Node.js ≥ 20.19. При первом запуске Wave сам скачает **yt-dlp** (с проверкой контрольной суммы) и обновляет
его раз в 12 часов — YouTube часто меняется. **ffmpeg** ставится вместе с зависимостями (`ffmpeg-static`).

> Если окно не появляется, а в консоли `Cannot read properties of undefined (reading 'isPackaged')` —
> в окружении выставлена `ELECTRON_RUN_AS_NODE`. Скрипты `npm run …` её сбрасывают сами.

## Что умеет

**Импорт** (кнопка «Добавить музыку», либо просто Ctrl+V со ссылкой в любом месте окна, либо перетащить ссылку/файлы)

| Источник | Как работает |
|---|---|
| YouTube / YouTube Music | видео, плейлисты, каналы; yt-dlp, лучший аудиопоток без перекодирования |
| SoundCloud | треки, сеты, профили; yt-dlp. Отдельное окно «Профиль SoundCloud» (Добавить → «Профиль SoundCloud →»): по имени или ссылке импортирует **лайки** (в «Любимое», до 1000 последних; лайкнутые чужие плейлисты пропускаются) и выбранные **плейлисты** профиля отдельными плейлистами. Работает с публичными профилями, входить в аккаунт не нужно |
| Deezer | трек / альбом / плейлист по публичному API без ключей; звук ищется на YouTube Music |
| Spotify | трек / альбом / плейлист по ссылке, без ключей. Звук Spotify защищён DRM, поэтому трек **ищется на YouTube Music** по названию и длительности (оценка совпадений в [matcher.ts](src/main/services/matcher.ts)); обложка и теги берутся из Spotify |
| Яндекс Музыка | трек / альбом / плейлист. С токеном (Настройки → Загрузки → «Войти через Яндекс») качается оригинал, с Plus — до FLAC; без токена ищется на YouTube Music |
| Apple Music | песня / альбом / плейлист по ссылке `music.apple.com`, без ключей: список берётся с публичной страницы и iTunes API, а звук **ищется на YouTube Music** (как у Spotify — у Apple он под DRM) |
| Название песни | напишите «исполнитель — название», Wave найдёт варианты |
| Свои файлы | перетащите аудио или папку в окно; файлы остаются на месте |
| Видео | MP4, MOV, MKV и др.: Wave **вытаскивает звуковую дорожку без перекодирования** (AAC остаётся AAC) в папку музыки, а кадр из видео становится обложкой. Исходное видео не меняется |

**Качество звука.** Wave никогда не перекодирует скачанное: Opus остаётся Opus, AAC — AAC, FLAC — FLAC. Потолок задаёт
источник: YouTube отдаёт Opus ≈ 130–160 kbps (до 256 kbps с YouTube Premium), SoundCloud — 128 kbps MP3 (256 kbps AAC с Go+),
Яндекс — FLAC с Plus. Чтобы получить повышенное качество подписок, выберите браузер в Настройки → Загрузки → «Куки браузера».
В плеере: значок качества (кодек, битрейт, разрядность), выравнивание громкости по EBU R128 (замер при загрузке, без пересжатия),
10-полосный эквалайзер с автоматическим запасом от клиппинга, выбор устройства вывода. Эквалайзер и все эффекты по умолчанию выключены.

**Звуковые эффекты** (кнопка с ползунками в плеере → «Эффекты»; Настройки → Звук): темп без смены тона, сдвиг тона ±12 полутонов, бас-буст,
дисторшн, реверберация (длина «хвоста» настраивается), пресеты: Nightcore, Slowed + Reverb, Lo-fi и др. При включении эффектов громкость
автоматически снижается, чтобы не было клиппинга. Сдвиг тона — «две линии задержки с пилой», на сдвигах больше ±6 полутонов слышен лёгкий хорус.

**Кроссфейд и gapless** (Настройки → Звук): плавный переход 0–12 с или переход без паузы. Следующий трек заранее подгружается на вторую «деку» плеера.
Gapless — «почти без паузы»: следующий трек стартует за ~0.12 с до конца, чтобы компенсировать запуск декодера; нулевой зазор для
сведённых без пауз альбомов этим способом не гарантируется.

**Эмбиент** (кнопка в плеере → «Эмбиент»): дождь, океан, камин поверх музыки, у каждого свой ползунок и несколько готовых смесей. Звуки
синтезируются прямо в приложении из шума (файлов нет), идут мимо эквалайзера и эффектов и продолжают играть на паузе.

**Волна и анализ трека.** Полоса перемотки показывает форму трека (можно вернуть обычную линию: Настройки → Оформление). В «Сейчас играет» →
«Анализ»: темп (BPM), тональность и код Camelot, громкость (LUFS), пик, динамика (пик минус громкость), «характер» — энергия, бас, вокал, яркость —
и список **похожих треков в вашей медиатеке** (по темпу, тональности по кругу Camelot, тембру и энергии). Всё считается локально
(ffmpeg декодирует, дальше собственный FFT в [analysisDsp.ts](src/main/services/analysisDsp.ts)), результаты кэшируются в `~/.config/Wave/analysis`;
библиотека анализируется в фоне по одному треку. Это **оценки**, а не измерения: тональность определяется по профилям Крумхансла, темп — по автокорреляции
всплесков, поэтому темп иногда определяется вдвое выше/ниже настоящего, а на ambient, речи и нестандартных размерах оба показателя могут ошибаться.
«Энергия», «бас», «вокал», «яркость» — эвристики по частотным полосам, а не оценка слушателя; «вокал» — это доля мощности в диапазоне 300–3400 Гц,
вокал как таковой не распознаётся. Треки длиннее 30 минут не анализируются.

**Тексты и караоке.** Порядок поиска: `.lrc` рядом с файлом → Яндекс → [LRCLIB](https://lrclib.net) (тайминги по строкам) → Genius (обычный текст).
Genius не публикует тайминги и не отдаёт тексты через API, поэтому **синхронизацию дают LRCLIB и Яндекс**, а Genius — обычный текст.
Поиск по Genius нечёткий: из тегов убираются «(@ник)» у исполнителя и «(prod. by …)» в названии, кириллица сравнивается через транслит
(«Юпи» ↔ «Jupi»), ник и продюсер из скобок используются как псевдонимы исполнителя, пробуется несколько запросов (в том числе «все песни исполнителя»).
Уверенное совпадение подставляется само; если название на Genius переведено или написано иначе и уверенности нет, под «Текст не найден» показываются
найденные страницы — выбираете нужную одним нажатием — и поле, куда можно вставить ссылку на страницу Genius. Заглушки вроде «Unknown Artist» исполнителем не считаются.
Genius защищает страницы от программ: если он отвечает защитной страницей, Wave честно об этом говорит (обходить защиту он не пытается)
и предлагает открыть страницу в браузере и вставить текст кнопкой «Вставить текст». Если есть только обычный текст,
его можно разметить вручную («Синхронизировать» — нажимаете Пробел в начале каждой строки). Для караоке: подсветка строки,
плавная заливка, автопрокрутка, клик по строке — перемотка, сдвиг ±0.25 с, размытие дальних строк.

**Оформление и кастомизация** (Настройки → Оформление). Дизайн в стиле iOS: плавающая боковая панель и мини-плеер,
крупные заголовки, сгруппированные списки. Настраивается почти всё:
- **готовые стили** (iOS, iOS светлая, Жидкое стекло, Матовое, AMOLED, Минимализм, Уютный) и **«Мои стили»**: сохранить текущее
  оформление, применить, перезаписать, удалить, **экспорт/импорт в файл** `.wave-style.json`, чтобы делиться;
- 10 тем, любой акцент или цвет из обложки (текст на акценте сам становится тёмным, если акцент светлый), **свои цвета** фона, поверхностей,
  текста, подписей и разделителей поверх темы;
- **стекло**: выключено / матовое / жидкое; плотность, размытие, насыщенность, блики и кант, оттенок, **преломление** фона
  (SVG-фильтр в `backdrop-filter`, работает в Chromium; нагружает видеокарту);
- фон: однотонный / размытая обложка / градиент из обложки / **фото, GIF или видео** (видео играет без звука по кругу и на паузе, когда окно скрыто), затемнение;
- раскладка: боковая панель плавающая или у края и её ширина, плеер плавающий или панелью снизу, поиск в боковой панели или сверху;
- форма: скругление углов и обложек, кнопки-капсулы / скруглённые / прямые, сила теней, разделители в списках;
- текст: 5 шрифтов, размер текста, размер и насыщенность заголовков, толщина линий иконок; масштаб всего интерфейса, плотность списков, размер карточек;
- порядок и видимость разделов главной, видимость пунктов боковой панели, скорость анимаций, вид полосы перемотки, визуализатор, настройки караоке.

Все параметры доступны в своём CSS как переменные (`--accent`, `--radius`, `--blur`, `--glass-op`, `--fs`, `--btn-r` …), а состояние — как атрибуты
`<html>` (`data-glass`, `data-sidebar`, `data-player`, `data-theme`). Стили — [ios.css](src/renderer/src/styles/ios.css).

**Свой CSS и плагины** (Настройки → Расширения). CSS применяется поверх темы сразу. Плагины — папки в `~/.config/Wave/plugins/<id>/` с `plugin.json`
(`name`, `version`, `main`, необязательно `style`); при первом запуске создаётся пример. Плагин получает `window.WaveAPI` (плеер, чтение библиотеки,
уведомления, настройки). **Плагин выполняет произвольный код с доступом к вашей библиотеке и настройкам — включайте только те, которым доверяете.**
По умолчанию все плагины выключены.

**Аккаунт и синхронизация** (Настройки → Аккаунт). Облака у Wave нет: синхронизация идёт через **ваш собственный сервер**, который запускается одной командой
`npm run server` (один файл [server/server.mjs](server/server.mjs), без зависимостей). Переменные: `PORT` (8787), `HOST` (127.0.0.1),
`WAVE_SERVER_DATA` (папка данных), `WAVE_ALLOW_REGISTER=0` — закрыть регистрацию, когда аккаунты созданы. Сервер говорит по HTTP, а пароль нельзя пускать
по сети открытым текстом, поэтому для доступа не из localhost поставьте перед ним HTTPS-прокси (Caddy, nginx); клиент отказывается подключаться
к чужому адресу без `https://`. Синхронизируется **описание** библиотеки: названия и источники треков, любимое, плейлисты, число прослушиваний,
оформление, звук (кроме громкости и устройства вывода) и свой CSS. Аудиофайлы, токены сервисов и пути к файлам на сервер не попадают; на втором
устройстве недостающие треки докачиваются кнопкой «Скачать недостающие». Пароли хранятся как scrypt-хэши, сессии — как хэши токенов.
Конфликты решаются так: «любимое», плейлисты и настройки — побеждает более поздняя правка, удаления не воскрешают треки, удаление не затрагивает файлы на других устройствах.

**Аккаунт, витрина и итоги года** (аватар внизу боковой панели). Витрина — профиль в духе Discord: имя, местоимения, статус с эмодзи, «о себе»,
аватар (можно анимированный GIF) с формой и рамкой, баннер (градиент, цвет, картинка или обложка трека), палитра, вид карточки (стекло, градиент,
сплошной, контур), эффекты (сияние, боке, звёзды, снег, волны, плёнка), шрифт и стиль имени. Блоки ставятся в любом порядке и в половину или всю ширину:
статистика (выбранные показатели за неделю/месяц/год/всё время), любимые треки/исполнители/альбомы (топ или свой выбор; список, плитка, пьедестал, лента),
трек-визитка, плейлист, «сейчас слушаю», текст, ссылки, значки, активность по дням, часы прослушивания, итог года, цитата; есть шаблоны.
Статистика строится по истории прослушиваний (`listens/<год>.json`: трек, время, сколько секунд реально звучал); счётчики, накопленные до её появления,
учитываются как приблизительная часть. «Итоги года» — истории на весь экран: минуты, первый трек года, исполнитель и песня года, топ-5, время суток,
самый музыкальный месяц, рост медиатеки, музыкальный тип; итоговую карточку можно сохранить в PNG, собрать из неё плейлист и поставить на витрину.
Если выполнен вход на сервер синхронизации и включено «Показывать витрину другим», витрина публикуется там же (имя, картинки, тексты и уже посчитанные
блоки с маленькими обложками — без файлов и путей) и видна другим пользователям этого сервера в «Люди на сервере»; для этого нужна свежая версия server.mjs.

**Интерфейс** (каркас — по мотивам Riff и Spotify, палитра и шрифт — собственные Wave): слева панель «Медиатека» (плейлисты с обложками, альбомы, очередь,
фильтр; сворачивается в рейку иконок), сверху «Домой» и поиск с результатами по разделам (лучшее совпадение, исполнители, альбомы, плейлисты, треки),
справа «Сейчас играет» (обложка, авторы, источник звука, темп/тональность), внизу плеер с волнистой перемоткой и общим окном «Аудио»
(эквалайзер, эффекты, эмбиент, таймер сна). При первом запуске пустой библиотеки показывается короткое приветствие. Тема «Material You» (цвета из обложки) осталась в настройках как один из вариантов.

**Веб-импорт (слушать без скачивания).** В окнах импорта есть флажок «Без скачивания (слушать онлайн)»: трек попадает в библиотеку без файла (значок WEB),
а звук берётся из интернета при воспроизведении. Прямые файлы (YouTube) идут через встроенный прокси с перемоткой, потоки HLS (так сейчас отдаёт SoundCloud) —
через hls.js и тот же прокси. У веб-треков нет файла, поэтому для них недоступны вырезание, анализ и сохранение .lrc; платные/DRM-треки SoundCloud не играют ни так, ни так.
Spotify/Apple/Deezer/Яндекс при этом флажке всё равно скачиваются (их звук ищется на YouTube).

**Караоке.** Тексты ищутся в LRCLIB по нескольким вариантам названия и ника (скобки «prod./feat.», «onda_andar», «Юпи (@ник)»), синхронизация берётся только если длительность версии близка.
Если точных таймингов нет, а обычный текст есть, строки раскладываются по времени примерно (метка «примерно по тексту») — это приближение, не распознавание речи; точные тайминги можно расставить вручную («Точная синхронизация»).

**Улучшение звука** (окно «Аудио» → «Улучшение»): ясность вокала, воздух, тепло, плотность — набор фильтров и мягкий компрессор, не нейросеть и не «восстановление» качества.

**Ещё:** вырезание фрагмента без потерь, таймер сна (через N минут или до конца трека, с плавным затуханием), Discord Rich Presence (нужен свой Application ID).

**Библиотека:** треки/альбомы/исполнители, плейлисты, любимое, очередь, сортировка, поиск (Ctrl+K), мультивыбор, контекстное меню,
правка тегов и обложки, медиаклавиши и интеграция с системой (MPRIS на Linux).

Горячие клавиши: `Пробел` — пауза, `Ctrl+←/→` — трек, `L` — караоке, `Q` — вкладка «Очередь», `Ctrl+K` — поиск, `Ctrl+V` — вставить ссылку.

## Где что лежит

- Музыка: `~/Music/Wave` (меняется в настройках), файлы называются `Исполнитель - Название.ext`, теги и обложка вшиты.
- Данные приложения (библиотека, настройки, тексты, обложки, yt-dlp): `~/.config/Wave` (кнопка в Настройки → О программе).

```
src/main        процесс Electron: библиотека, загрузки, источники, тексты
  services/     binaries (yt-dlp/ffmpeg), ytdlp, downloader, matcher, lyrics, genius, lrc, localImport, analysis(+Dsp), sync, plugins, sources/{spotify,apple,deezer,yandex,generic}, discord, trim
src/preload     безопасный мост (contextIsolation, sandbox)
src/renderer    интерфейс на React + Zustand; lib/audio.ts — аудиодвижок на Web Audio, lib/effects.ts — питч, реверб, дисторшн, эмбиент
server          сервер синхронизации (npm run server)
src/shared      общие типы и контракт IPC
```

## Что проверено, а что нет

Проверено в работающем приложении: сборка и режим разработки, все экраны, воспроизведение и цепочка Web Audio (спектр реагирует на звук),
караоке, очередь, эквалайзер, динамический акцент, импорт своих файлов, разбор ссылок Spotify (трек, альбом, плейлист на 50 треков),
получение текстов (LRCLIB, Genius), запись тегов/обложек в Opus/M4A/MP3/FLAC, замер громкости, парсер LRC, оценка совпадений.

Для новых возможностей: импорт видео (3 ролика MP4 → звук + обложка), разбор ссылок Apple Music вживую (песня, альбом, плейлист на 50 треков),
синхронизация двух «устройств» против настоящего сервера (конфликты, удаления, отсутствие зацикливания, выход из аккаунта), анализ треков в приложении
(волна, карточка анализа, кэш, похожие), тональность на 7 синтетических аккордовых последовательностях (7 из 7) и темп на 8 синтетических ритмах
(5 из 8 точно, в остальных — ошибка в октаву), синтез эмбиента в OfflineAudioContext (без NaN и клиппинга, «качание» океана видно по уровню).

Для последних изменений: импорт SoundCloud проверен на реальном публичном профиле (список из 18 плейлистов, чтение 795 лайков, пропуск 205 лайкнутых плейлистов — без скачивания треков),
таймер сна «до конца трека» (после 7-секундного трека следующий не стартует), вырезание фрагмента (точная копия 7,5 с с обложкой), Discord — только против поддельного IPC-сервера,
новый интерфейс — скриншотами в рабочем приложении (главная, плейлист, «Любимое», поиск, окно «Аудио», приветствие).

Веб-импорт: HLS-прокси проверен на реальном бесплатном треке SoundCloud (плейлист, init-сегмент и медиа-сегменты, отказ для чужих хостов), воспроизведение через hls.js — в приложении (время шло, 0:10 → 0:18);
поиск текстов — на 6 тестовых треках (3 найдены синхронизированными).

**Не проверено** (в среде разработки не было такой возможности):
- веб-треки YouTube (обычный файл с Range) в приложении, перемотка и кроссфейд для веб-треков (их следующий трек не подгружается заранее — переход идёт обычным путём);
- звучание «Улучшения» на слух (граф собирается и работает без ошибок);
- Discord Rich Presence против настоящего клиента Discord (протокол написан и прогнан только против тестового сервера);
- загрузка самих треков из SoundCloud-лайков и плейлистов (список и разбор проверены, скачивание — стандартным путём yt-dlp, как для одиночных треков);
- закрытые профили SoundCloud и приватные лайки: yt-dlp без входа их не видит, приложение покажет ошибку;
- **на слух** ничего из звука не проверялось: эффекты (питч, реверб, дисторшн, темп), кроссфейд/gapless и эмбиент проверены по графу и по измерениям сигнала, а не ушами;
  как звучит питч-шифтер и насколько незаметен переход в gapless — решит первое прослушивание;
- точность темпа и тональности на реальной музыке: проверялось на синтетике и на трёх коротких роликах, а не на выборке настоящих песен;
- скачивание через yt-dlp треков, найденных по ссылкам Apple Music (поиск совпадений на YouTube Music проверен, сама загрузка — нет);
- синхронизация через интернет/HTTPS-прокси: тестировалась только по localhost;
- сквозная загрузка через yt-dlp (YouTube, SoundCloud, поиск совпадений для Spotify) — код написан по документации yt-dlp, первый реальный запуск покажет детали;
- Яндекс Музыка: из среды разработки API отвечает 451, поэтому вход, получение файла (подпись и расшифровка) и тексты Яндекса написаны по описанию неофициального API и ни разу не запускались;
  при любой ошибке загрузчик откатывается к поиску на YouTube Music;
- сборка установщика (`npm run dist`) и работа на Windows/macOS.

## Известные ограничения

- Spotify без входа отдаёт не больше 100 треков плейлиста; «Любимые треки» и приватные плейлисты по ссылке недоступны.
- Gapless — «почти без паузы» (см. выше), а не побитово точный; при включённых эффектах переход между треками тоже проходит через общую цепочку эффектов.
- Фоновый анализ библиотеки использует процессор (по одному треку за раз, 3–5 секунд на трек): на большой библиотеке в первые минуты может быть заметна нагрузка.
- Аудиовыход идёт через движок Chromium → системный звуковой сервер; режима «bit-perfect/exclusive» нет.
- Загружайте только то, что вы вправе сохранять, и соблюдайте условия сервисов-источников.
